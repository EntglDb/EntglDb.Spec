Progetto 1 di 2

EntglDb

Middleware di sincronizzazione P2P per applicazioni offline-first. Protocollo v5, disponibile per .NET 8/10.

Offline-First

L'app funziona senza connessione. I dati si sincronizzano automaticamente quando i peer tornano online.

Peer-to-Peer

Comunicazione diretta tra dispositivi via TCP. Discovery UDP locale. Nessun cloud obbligatorio.

Conflict Resolution

LWW (Last-Write-Wins) e RecursiveMerge per fusione automatica di documenti JSON concorrenti.

Sicurezza

Handshake ECDH + AES-256, OAuth2 JWT per Cloud Node, Brotli compression.

Progetto 2 di 2

BLite

Database BSON embedded, zero-dipendenze. Targets: net10.0 + netstandard2.1. Compatibile con MAUI, Xamarin, Unity.

Zero Allocation

Parsing BSON con Span<T> stack-only. Zero garbage nelle query hot path.

LINQ Provider

B-Tree indexes. Query con predicati C# compilati. BLQL per query da stringa.

Vector Search

HNSW graph (cosine/euclidean). R-Tree geospatiale. CDC per change streaming.

Kotlin / Android EntglDb

Progetto 1 — Kotlin Porting

Goal: Implementare EntglDb.Kotlin da zero, partendo da uno scaffold Gradle già strutturato. Riferimento: EntglDb.Net v1.0.0.

Moduli:

  • :core — VectorClock, HLC, OplogEntry, Conflict Resolution
  • :persistence-sqlite — Room / SQLiteDatabase adapter
  • :network — TCP Client/Server, UDP Discovery, Handshake (proto v5)
  • :protocol — Protobuf deserialization (già generato)
  • :app — Demo Android (offline-first TODO list)

Stack: Kotlin 2.x · JDK 21 · Android API 24+ · Gradle 8 · Protobuf v5

.NET 8/10 Algorithm

Progetto 2 — Conflict Resolution

Goal: Estendere il sistema di conflict resolution di EntglDb.Net con un motore di merge tre-vie basato su JSON Diff/Patch (RFC 6902).

Attività:

  • Implementare IDocumentMerger con strategia 3-way merge
  • Delta computation (JSON Patch ops: add, remove, replace, move)
  • Merge automatico di campi non-conflittuali
  • Strategie per array: union, last-write, custom comparator
  • Test suite + NuGet package EntglDb.ConflictResolution

Stack: C# 13 · .NET 8/10 · xUnit · NuGet packaging

BLite Observability

Progetto 4 — Audit & Monitoring

Goal: Aggiungere un layer di audit/observability a BLite con overhead zero quando disabilitato (JIT branch elimination).

Componenti:

  • Phase 1 — IBLiteAuditSink (events), BLiteMetrics (Interlocked counters), BLiteAuditOptions
  • Phase 2 — BLiteDiagnostics (ActivitySource / OpenTelemetry), slow-query detection
  • Hook points: CommitTransaction, InsertDataCore, Execute<TResult>
  • Sink predefiniti: Console, JSON file, OpenTelemetry OTLP

Spec dettagliata in BLite/AUDIT_IMPLEMENTATION.md

BLite MAUI AI

Progetto 5 — BLite Mobile + AI

Goal: App .NET MAUI con semantic search offline usando BLite HNSW + ML.NET + ONNX.

Pipeline:

  • Testo → MiniLM-L6-v2 (ONNX, 384 dim) → float[] embedding
  • Embedding salvato in BLite con HNSW index
  • Query semantica: "trova note simili a …" in < 50 ms
  • UI MAUI: note manager con ricerca ibrida (keyword + semantica)

Stack: .NET MAUI · ML.NET 3.x · ONNX Runtime · BLite NuGet · C# 13

AI .NET

Progetto 6 — Restaurant Menu Importer

Goal: Pipeline AI che estrae dati strutturati da menu di ristoranti (URL, PDF, foto, testo libero) e restituisce JSON normalizzato.

Pipeline:

  • Ingestion — URL scraping / PDF text extract / OCR (Tesseract)
  • LLM Extraction — Ollama (Mistral/LLaMA3) o Azure OpenAI con prompt strutturato
  • Schema output — { categories[], items[{ name, price, allergens }] }
  • Validation — JSON Schema, convalida prezzi e allergeni
  • UI minima: paste URL → visualizza menu strutturato

Dominio: Zucchetti Hospitality — reale applicabilità industriale

AI BLite

Progetto 7 — Document Q&A (RAG)

Goal: Chatbot locale che risponde a domande su un corpus di documenti usando il pattern RAG (Retrieval-Augmented Generation).

Pipeline:

  • Chunking — Divide documenti in chunk da ~500 token con overlap
  • Embedding — MiniLM-L6-v2 (ONNX) → float[384] per chunk
  • Index — BLite HNSW per similarità coseno ultraveloce
  • Retrieval — Top-K chunk estratti dalla query utente
  • Generation — Ollama (LLaMA3/Phi-3) con contesto iniettato nel prompt

100% offline · nessun cloud · privacy-preserving · C# 13 · .NET 9/10
